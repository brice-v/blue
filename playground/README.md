# blue playground

A small, self contained webpage for trying out the blue language entirely in
the browser. No server side execution, no network round trips: the whole
interpreter is compiled to WebAssembly and runs inside your tab.

## Files

- `index.html` - the page
- `app.js` - wires the editor to the wasm runtime, captures output
- `style.css` - minimal styling, no external assets
- `blue.wasm` - the compiled runtime (generated by [`../make_wasm.sh`](../make_wasm.sh))
- `wasm_exec.js` - go's js/wasm support file (copied from your go install)

`blue.wasm` and `wasm_exec.js` are generated; run this from the repo root:

```sh
./make_wasm.sh
```

## Running it

Browsers do not allow `fetch` of local files from `file://` pages, so serve
the directory over http:

```sh
cd playground
python3 -m http.server 8787
```

then open <http://localhost:8787>. Any static file server works (the page
falls back from streaming instantiation if `.wasm` has the wrong MIME type).

## Sandboxing

This follows the usual client side language playground model (like in-browser
lua/python interpreters):

- The interpreter runs inside the WebAssembly sandbox of the browser tab.
  It only gains capabilities explicitly wired up in `app.js`, which are:
  running source code and collecting its printed output.
- **No filesystem**: go's js/wasm environment has a stub filesystem only.
  File builtins return runtime errors instead of touching your disk.
- **No processes or shell**: shell execution is hard disabled in the runtime
  (`object.NoExec = true`) and does not exist on js/wasm anyway.
- **No network by default**: the page loads only same origin files. Note that
  blue's `http.get` style builtins map onto browser fetch on js/wasm, so such
  calls behave like any web page: subject to CORS and visible in devtools.
  Server builtins (`http.serve` etc) cannot listen from a browser context.
- A strict Content-Security-Policy allows scripts only from this origin plus
  `'wasm-unsafe-eval'` (required for WebAssembly compilation). No CDN, no
  inline script, no eval.
- gui modules (`gg`, `ui`) and host dependent modules (`db`, `config`,
  `psutil`) are stubbed out at build time via build tags; calling them
  returns a clear "not available in the wasm build" error.

### Known limitation

Blue programs run synchronously on the page's main thread, so an infinite
loop will freeze the tab until you reload it.

## Rebuilding after interpreter changes

```sh
./make_wasm.sh   # rebuilds playground/blue.wasm
```
